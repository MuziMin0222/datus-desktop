# Datus Desktop 部署文档

本文说明如何构建、打包、发布 Datus Desktop，以及如何为桌面端部署远程 `datus-api` 后端。

- 桌面端仓库：`datus-desktop`（Electron + React + TypeScript）
- 后端引擎：`Datus-agent`（Python 3.12+，提供 REST + SSE）

---

## 1. 运行模式与平台支持

| 模式 | 平台 | 后端来源 | 说明 |
|---|---|---|---|
| 本地模式 | macOS Apple Silicon、Linux x86_64 / arm64 | 应用首启动时用内置 `uv` 安装 Python 3.12 + 固定版本 `datus-agent`，再拉起 `datus-api` 子进程 | 开箱即用，首次启动需要联网 |
| 远程模式 | 全部平台（含 Windows 11） | 连接一台已部署的 `datus-api` | Windows 只能使用远程模式 |

> Windows 无法本地运行后端：`dosi-engine` 目前只提供 Linux x86_64/aarch64 与 macOS arm64 的 wheel。

桌面端在本地模式下会在 `127.0.0.1` 随机端口启动后端，并注入每次启动随机生成的 Token；进程随桌面端退出而终止。

## 2. 环境准备

### 2.1 构建机依赖

- Node.js 24（仓库在 Node 22/24 + npm 10 下验证）
- npm（仓库内 `.npmrc` 已设置 `legacy-peer-deps=true`）
- macOS 打包需 Xcode Command Line Tools
- 本地开发调试后端时，需要一份已 `uv sync` 的 `Datus-agent` 仓库

### 2.2 获取代码与安装依赖

```bash
git clone <datus-desktop 仓库地址>
cd datus-desktop
npm install
```

### 2.3 准备随包资源

```bash
npm run fetch:uv          # 下载当前平台的 uv 二进制到 resources/uv/<platform>-<arch>/
npm run vendor:artifact   # 下载 @datus/web-artifact-render@2.0.0 的 UMD 到 resources/artifact-render/
```

这两步产物都已加入 `.gitignore`，但打包前必须存在：

- `resources/uv/<triple>/uv`：本地模式引导 Python 用
- `resources/artifact-render/index.umd.js|index.css`：报表/看板预览用
- `resources/agent-pin.json`：固定后端版本
- `resources/config/base.agent.yml`：本地模式生成的初始 `agent.yml`

`resources/agent-pin.json` 示例：

```json
{
  "datusAgentVersion": "0.4.6",
  "pythonVersion": "3.12",
  "uvVersion": "0.9.0",
  "datusAgentWheel": "https://github.com/MuziMin0222/datus-agent/releases/download/v0.4.6/datus_agent-0.4.6-py3-none-any.whl"
}
```

`datusAgentWheel` 是桌面端配套的后端 wheel：同版本的 PyPI 包不含 `/health/live`、Token 鉴权、
`source="desktop"` 与配置写入固定等改动，因此本地模式必须安装这个 wheel。首次启动时会从该 URL 下载；
如需内网离线安装，可把 wheel 放到镜像地址并修改此字段。

发布前请把 `datusAgentVersion` 与后端 release tag 对齐，并同步更新 `datusAgentWheel`。

## 3. 本地开发

```bash
npm run dev
```

开发模式行为：

- 使用 `DATUS_DESKTOP_DEV=1` 时跳过 uv 引导
- 默认使用 `../Datus-agent/.venv/bin/python`；可用 `DATUS_DEV_PYTHON` 覆盖
- Datus-agent 仓库位置默认 `../Datus-agent`；可用 `DATUS_REPO` 覆盖
- 使用默认用户目录持久化设置

常用环境变量：

| 变量 | 作用 |
|---|---|
| `DATUS_DESKTOP_USER_DATA` | 覆盖应用数据根目录（设置、运行时、日志） |
| `DATUS_DESKTOP_DEV=1` | 强制开发模式（跳过 uv 安装） |
| `DATUS_REPO` | Datus-agent 源码路径 |
| `DATUS_DEV_PYTHON` | 指定开发用 Python 可执行文件 |
| `DATUS_PIP_INDEX` | 安装 datus-agent 时使用自定义 PyPI 镜像 |
| `DATUS_UV_PATH` | 指定 uv 二进制路径 |
| `DATUS_DESKTOP_DISABLE_UPDATES=1` | 禁用自动更新检查 |

## 4. 测试

```bash
npm run typecheck   # main / renderer / e2e 三套 TypeScript 检查
npm run test:unit   # Vitest：SSE 解析、聊天 reducer、代理执行器、artifact HTML
npm run test:e2e    # 构建后启动真实 Electron，连接本地 mock 后端跑一轮对话
```

e2e 不依赖 Python、LLM 或外网：测试进程内启动 HTTP mock（含 CORS 与 SSE），用隔离的用户目录以远程模式启动应用。

## 5. 构建与打包

```bash
npm run build       # 产物在 out/（main / preload / renderer）
npm run dist:mac    # release/<version>/Datus Desktop-<version>-arm64.dmg + zip
npm run dist:win    # NSIS 安装包
npm run dist:linux  # AppImage + deb
```

产物说明：

- 打包会把 `resources/` 复制到应用 Resources 目录（含 uv、artifact 渲染器、配置模板）
- `electron-builder.yml` 中 `extraResources` 已配置
- 当前默认不签名/不公证
- 建议在对应平台构建（CI 已按 macOS / Windows / Linux 矩阵执行）；跨平台构建 Windows 包通常需要额外工具链

### 5.1 macOS 签名与公证

macOS 自动更新要求应用已签名并公证。准备 Developer ID 证书后：

1. 在 `electron-builder.yml` 中设置 `notarize`（或使用 electron-builder 的 `notarytool` 配置）
2. 在 CI/本地注入 `CSC_LINK`、`CSC_KEY_PASSWORD`、`APPLE_ID`、`APPLE_APP_SPECIFIC_PASSWORD`、`APPLE_TEAM_ID`
3. 确认 `build/entitlements.mac.plist` 已包含 JIT 与网络权限

未签名包在本机可右键“打开”绕过 Gatekeeper，但不适合分发。

## 6. 发布与自动更新

自动更新使用 `electron-updater`，更新源由 `electron-builder.yml` 的 `publish` 决定（当前 GitHub：`MuziMin0222/datus-desktop`）。

发布流程建议：

1. 修改 `package.json` 版本号，并同步 `resources/agent-pin.json` 中的后端版本
2. 打 tag（如 `v0.2.0`），CI 会构建三平台产物
3. 上传/发布 GitHub Release（当前 `releaseType: release`，发布后更新才会推送给用户）
4. 已安装客户端：启动 5 秒后自动检查；也可在“设置 → Updates”手动检查
5. 下载完成后显示“Restart to install”

注意：

- 开发版永远显示 “Development builds do not auto-update”
- macOS 未签名包无法完成自动更新
- 可通过 `DATUS_DESKTOP_DISABLE_UPDATES=1` 关闭检查

## 7. 远程后端部署（datus-api）

### 7.1 后端版本要求

远程模式依赖以下后端能力，必须使用包含这些改动的 Datus-agent 版本：

| 能力 | 用途 |
|---|---|
| `GET /health/live` | 轻量就绪探针（不探测 DB/LLM） |
| `DATUS_API_TOKEN` Bearer 鉴权 | 远程访问鉴权（豁免 health 与 CORS 预检） |
| `source="desktop"` 会话语义 | 服务端执行文件系统工具，不代理给客户端 |
| `--config` 固定配置写入路径 | `PUT /config/*` 写入指定配置文件 |

> 若使用 PyPI 上的旧版本，上述接口可能不存在，桌面端远程模式将无法连接或鉴权。

### 7.2 安装后端

Linux x86_64/aarch64 或 macOS：

```bash
curl -fsSL https://raw.githubusercontent.com/datus-ai/datus-agent/main/install.sh | sh
# 或
pip install datus-agent
```

### 7.3 启动服务

```bash
export DATUS_API_TOKEN="$(openssl rand -hex 32)"
datus-api \
  --host 0.0.0.0 \
  --port 8000 \
  --config /srv/datus/agent.yml \
  --datasource demo
```

说明：

- Token 未设置时后端保持无鉴权（只适合本机回环）
- `/health` 与 `/health/live` 不需要 Token
- 单 Token 单租户；多用户/RBAC 需自行在前面加网关
- 工作目录（CWD）即项目根：报表/看板、`subject/` 知识库都在该目录下

### 7.4 TLS 与反向代理

Token 会随请求传输，跨网络必须使用 HTTPS。Caddy 示例：

```caddyfile
datus.example.com {
  reverse_proxy 127.0.0.1:8000
}
```

nginx 需关闭 SSE 缓冲：

```nginx
location / {
  proxy_pass http://127.0.0.1:8000;
  proxy_http_version 1.1;
  proxy_set_header Host $host;
  proxy_buffering off;
  proxy_read_timeout 3600s;
}
```

### 7.5 桌面端连接

在桌面端初始向导选择“Remote server”：

- Server URL：`https://datus.example.com`（必须包含协议）
- Access token：与 `DATUS_API_TOKEN` 一致
- 自签名证书可勾选“Accept self-signed TLS certificates for this host”

Token 会通过 Electron `safeStorage` 存入系统钥匙串，不写入明文配置。

### 7.6 数据与备份

后端数据默认位于启动用户的主目录下（`~/.datus/`），项目知识库在启动目录的 `subject/`。备份时至少保留：

- `agent.yml`（模型/数据源配置）
- `~/.datus/sessions/`
- `~/.datus/data/`
- 项目目录下的 `subject/`、`reports/`、`dashboards/`

## 8. 客户端数据目录

macOS 默认：

```
~/Library/Application Support/datus-desktop/
├── settings.json                  # 模式、工作区、权限档位、远程地址
├── datus-home/conf/agent.yml      # 本地模式的后端配置（应用私有）
├── runtime/
│   ├── venv/                      # 本地模式 Python 环境
│   ├── python/                    # uv 管理的 Python 3.12
│   ├── uv-cache/
│   └── fastembed/                 # 向量模型缓存
└── logs/datus-api.log             # 后端日志
```

默认工作区：`~/Documents/Datus`（首次启动自动创建）。

- 远程模式下 `agent.yml`、会话、数据都在服务器上
- `DATUS_DESKTOP_USER_DATA` 可整体迁移数据目录（便于测试或便携部署）

## 9. CI（可选，默认不随仓库推送）

仓库本地保留了一份示例工作流 `.github/workflows/desktop.yml`，但它没有纳入版本控制（`.git/info/exclude` 已忽略 `.github/`）：

| Job | 触发 | 内容 |
|---|---|---|
| check | push / PR | typecheck + 单元测试 |
| e2e | push / PR | macOS 上运行 Playwright Electron e2e |
| build | 打 `v*` tag | 三平台打包并上传 artifact |

如需启用 GitHub Actions，可把该文件加入仓库并按第 5.1 节配置签名 secrets。注意：GitHub 的 OAuth 推送要求 `workflow` scope 才能创建 `.github/workflows/*`；改用 SSH 推送可绕过该限制。

## 10. 常见部署问题

### 10.1 启动报 `Invalid port: ':1]'`

原因：系统代理环境变量 `NO_PROXY` 含有 `[::1]`，httpx 在构造客户端时把它当 URL 解析失败。

桌面端已在拉起后端子进程时清洗 `NO_PROXY`（把 `[::1]` 转为 `::1`）。若仍看到该错误，确认运行的是修复后的版本；直接运行 `datus` CLI 时也可能遇到同样问题。

### 10.2 首次启动卡在安装

- 首次启动需要访问 `resources/agent-pin.json` 中 `datusAgentWheel` 指向的 GitHub Release 资产
- 检查网络与镜像：可设置 `DATUS_PIP_INDEX` 加速依赖下载
- 查看日志：设置 → View logs，或 `logs/datus-api.log`
- 安装失败后可删除 `runtime/venv` 重试（应用下次启动会重建）

### 10.3 远程连接 401

- 确认服务端设置了 `DATUS_API_TOKEN`
- 确认 Token 无多余空格
- 确认请求经过 TLS 反向代理时没有吞掉 `Authorization` 头

### 10.4 报表/看板一直 Loading

- 确认 artifact 位于**后端工作目录**下的 `reports/<slug>/` 或 `dashboards/<slug>/`
- 确认 `manifest.json` 与 `render/app.jsx` 存在
- 查看客户端日志中是否有 `/report/detail` 或 `/dashboard/detail` 的 4xx

### 10.5 macOS 提示应用已损坏

未签名/公证的包会被 Gatekeeper 拦截。开发自测可右键“打开”，正式分发请完成签名与公证。

### 10.6 Linux（麒麟）无法启动

新版 Electron 对 glibc 有最低要求。请在目标系统实测；若版本过旧，需要固定较老的 Electron 大版本或改用受支持的系统版本。
