# Datus Desktop 使用文档

Datus Desktop 是 Datus-agent 的桌面客户端：用自然语言问数、生成 SQL、构建语义模型、生成报表和看板，所有对话与工具调用都在桌面窗口里完成。

---

## 1. 启动应用

安装后直接打开 **Datus Desktop**。

首次启动会出现连接向导，二选一：

- **Local backend**：应用自动安装并启动本地后端（macOS Apple Silicon / Linux）
- **Remote server**：连接一台已部署的 `datus-api`（Windows 只能选这个）

连接成功后进入主界面：左侧是会话列表，右侧是对话区。

---

## 2. 首次配置

### 2.1 本地模式

1. 选择 **Local backend**
2. **Workspace folder** 选择工作目录（默认 `~/Documents/Datus`）
3. 选择 **Permission profile**（默认 `auto`）
4. 点 **Start local backend**

首次启动会下载 Python 3.12 与固定版本的 `datus-agent`，可能需要几分钟。进度与错误会显示在向导里，点 **View logs** 可查看详细日志。

> 需要联网。若安装失败，检查网络或配置 PyPI 镜像后重试。

### 2.2 远程模式

1. 选择 **Remote server**
2. 填写 **datus-api URL**（例如 `https://datus.example.com:8000`）
3. 填写 **Access token**（服务端启动时的 `DATUS_API_TOKEN`）
4. 如使用自签名证书，勾选 “Accept self-signed TLS certificates for this host”
5. 点 **Test connection** 确认可达，再点 **Connect**

Token 会加密存放在系统安全存储中（macOS 钥匙串 / Windows 凭据；Linux 无钥匙环时退化为仅当前用户可读的文件），不会以明文写入 `agent.yml`。

---

## 3. 设置页

左下角 **Settings** 打开设置，包含四块。

### 3.1 Connection

- 当前模式、服务地址、后端版本、工作区
- **Permission profile**：可随时切换（见第 7 节）
- **View logs**：查看后端最近日志
- **Change connection**：回到连接向导重新配置

### 3.2 Updates

- 显示当前客户端版本与更新状态
- **Check for updates**：手动检查
- 下载完成后出现 **Restart to install**
- 开发版会显示 “Development builds do not auto-update”

### 3.3 Model（配置大模型）

必填：

| 字段 | 说明 | 示例 |
|---|---|---|
| alias | 模型别名，保存后成为当前激活目标 | `my-gpt` |
| type | 供应商类型 | `openai` / `claude` / `deepseek` / `qwen` / `gemini` / `glm` / `kimi` / `minimax` / `openrouter` |
| model id | 具体模型名 | `gpt-4.1`、`deepseek-chat` |
| base_url | 可选，私有/兼容端点 | `https://api.example.com/v1` |
| api key | 可选；若使用环境变量可留空 | `sk-...` |

操作顺序：

1. 填写字段
2. 点 **Test**：会真的发一次探测请求，返回 “Model reachable.” 才算连通
3. 点 **Save & activate**：写入后端配置并设为当前模型

保存后配置写入当前后端使用的 `agent.yml`：本地模式是应用私有配置，远程模式是服务器上的配置；不会污染 `~/.datus`（本地模式已把配置路径固定在应用数据目录）。

> 也可以由运维在服务端 `agent.yml` 的 `providers` 中配置供应商级密钥；此时桌面端无需再填 api key。

### 3.4 Datasources（配置数据源）

- **sqlite / duckdb**：只填数据库文件路径
  - 例：`/Users/me/data/schools.sqlite`
- **snowflake / starrocks / postgresql / mysql**：填 host、port、username、password、database

点 **Add datasource** 保存。已配置的数据源会显示在列表里，例如 `demo (sqlite)`。

> 数据源路径/地址是**后端视角**的路径。本地模式下就是本机路径；远程模式下是服务器上的路径。

---

## 4. 开始对话

### 4.1 选择子 Agent

顶部下拉框选择子 Agent：

| 选项 | 用途 |
|---|---|
| Chat | 通用数据问答（默认） |
| Gen SQL | 专门生成/校验 SQL |
| Ask Metrics | 按指标定义回答业务问题 |
| Semantic Modeling | 生成/维护语义模型 |
| Visual Report | 生成 HTML 报表 |
| Visual Dashboard | 生成可交互看板 |
| Gen Table | 建宽表/生成建表语句 |
| Gen Job | 生成调度作业（如 Airflow） |

### 4.2 发送消息

- 在底部输入框输入问题，**Enter** 发送，**Shift+Enter** 换行
- 运行过程中，输入框变为 “Steer the running turn…”：此时发送会插入到当前轮次，用于纠偏或补充
- 点 **Stop** 可中断当前轮次

### 4.3 消息与工具卡片

对话区会实时展示：

- **Markdown 回答**：支持表格、代码块、列表
- **Thinking**：折叠的思考过程，点击展开
- **工具调用卡片**：显示工具名、参数、耗时、结果；点击卡片标题展开详情
  - `client` 徽标表示该工具由桌面端本地执行（本地模式 normal 权限下的写文件）
- **交互确认卡片**：需要你选择或补充信息时出现，选择后点 **Submit** 继续
- **错误块**：红色提示，通常带错误码

底部会显示 token 用量与会话上下文长度。

### 4.4 会话管理

- 左侧列表按子 Agent 展示历史会话
- 点击会话可恢复完整历史
- 悬停会话点 **×** 可删除
- **+ New chat** 开始新会话

---

## 5. 报表与看板预览

当子 Agent 产出报表/看板时，对话中会出现 artifact 卡片：

- **Open preview**：在应用内全屏预览
- **JSON detail**：查看后端返回的原始结构（排查问题时有用）

预览使用内置的 `@datus/web-artifact-render`，离线可用。看板中的实时查询会请求当前连接的后端。

> 如果预览一直 Loading，先确认 artifact 文件位于后端工作目录的 `reports/<slug>/` 或 `dashboards/<slug>/` 下，并包含 `manifest.json` 与 `render/app.jsx`。

---

## 6. 工作区与文件

- 本地模式下，Agent 的写文件/改文件/删文件操作默认限制在**工作区目录**内，路径逃逸会被拒绝
- 工作区可在连接向导中修改；切换后本地后端会重启
- 远程模式下，文件操作全部在**服务器工作目录**执行，桌面端不会读写你的本机文件

---

## 7. 权限档位

| 档位 | 行为 |
|---|---|
| normal | 读操作直接执行；写文件、SQL 写入、bash 命令需要确认 |
| auto（默认） | 工作区内写入与安全 SQL 自动执行；高风险操作仍会询问 |
| dangerous | 几乎全部自动执行，仅工作区外的写入会询问 |

提示：

- 本地模式 normal 下，写文件会以确认卡片形式询问，确认后由桌面端执行（会校验路径在工作区内）
- 远程模式没有“客户端文件”概念，文件工具始终在服务器执行
- 权限档位可在对话进行中切换

---

## 8. 数据与日志位置

macOS：

```
~/Library/Application Support/datus-desktop/
├── settings.json
├── datus-home/conf/agent.yml
├── runtime/          # 本地模式运行时
└── logs/datus-api.log
```

默认工作区：`~/Documents/Datus`。

远程模式下，配置、会话与数据都在服务器上。

## 9. 常见问题

### 9.1 发送消息提示没有可用模型

说明后端没有激活模型。到 **Settings → Model** 配置并 **Save & activate**；或在服务端 `agent.yml` 配置 `providers` 与 `target`。

### 9.2 配置模型时报 `Invalid port: ':1]'`

系统代理的 `NO_PROXY` 含 `[::1]` 导致 HTTP 客户端解析失败。桌面端已自动清洗该变量；若仍出现，确认客户端版本已更新。

### 9.3 Test connection 失败

- 检查 URL 是否包含 `http://` 或 `https://`
- 检查 Token 是否正确、是否有空格
- 检查反向代理是否转发 `Authorization` 头
- 在服务器上直接验证：`curl -H "Authorization: Bearer <token>" http://127.0.0.1:8000/api/v1/chat/sessions`

### 9.4 工具卡片一直 running

- 本地模式 normal 权限下，写文件需要你点确认；确认后才会返回结果
- 若确认卡片没出现，查看 **View logs** 是否有代理工具超时

### 9.5 应用启动后一直停在连接页

- 本地模式：点 **View logs** 查看 uv / Python 安装是否失败
- 远程模式：确认后端 `/health/live` 可访问

### 9.6 如何退出与重启后端

- macOS：关闭窗口后应用仍在后台运行（系统常规行为），本地后端也继续运行；点 Dock 图标可重新打开窗口。按 **Cmd+Q** 或菜单退出应用时，本地后端随之终止。
- Windows / Linux：关闭窗口即退出应用并终止本地后端。
- 下次启动应用会重新拉起后端。远程模式只影响本地客户端，不影响服务器。
